# 操作と検証

## 通常の使い方

1. `LocalVoiceBridge.exe`を起動します。
2. 通知領域で`Status: Ready`または`Status: Ready (existing)`を確認します。
3. デスクトップペットを左ダブルクリックするか、通知領域の`Show Local Voice panel`を選びます。
4. Windows Local Voice小窓で必要に応じて`キャラクター`と`音量`を設定し、`自動読み上げ`をオンにします。
5. Chrome / Braveで開いている任意のChatGPTタブへ新しいメッセージを送ります。
6. 新しい返答の冒頭プレビューが共通キューの順番で一度だけ再生されることを確認します。

Chrome / Brave内にはLocal Voice操作パネルを表示しません。日常操作はChrome外のWindows小窓だけで行います。小窓には`キャラクター`、`音量`、`マイク会話`、`自動読み上げ`、`次へ`、`再生成`、`停止`、`もう一度`、`詳細設定`、状態、現在文章、キュー数、登録済みChatGPTタブ数を表示します。`キャラクター`は内部では既存の`referenceVoice`設定を使い、空IDは`標準`として表示します。同じIDのペット素材がある場合はデスクトップペットも連動します。

`自動読み上げ`と`マイク会話`は独立した利用者設定です。自動読み上げをオフにしてもマイク会話を変更せず、マイク会話をオン・オフしても自動読み上げを変更しません。マイク会話中に通常Auto読み上げを一時抑制する既存の競合回避はruntime phaseで行い、永続設定を書き換えません。

`詳細設定`を押すとWindows詳細設定を開き、文字起こしモデル、送信前猶予、Live TTSプロファイルを変更できます。これらと`referenceVoice`、音量、マイク会話はLocal APIの永続設定が正本です。ブラウザ固有の読み上げ範囲だけは、詳細設定内の`ブラウザの読み上げ範囲設定`から拡張機能Optionsへ移動して変更します。

小窓には`Auto: 全3タブ · 操作対象: Tab B · 再生元: Tab A`のように、全タブAutoのscope、`次へ`/`再生成`の対象、現在または直前の再生元を表示します。この表示は既存のexternal state snapshotから作り、新しい高頻度pollや全タブbroadcastは追加しません。

拡張機能の切断と更新待ちは別状態です。切断中は自己reloadの成功を示さず再接続を待ちます。接続済みかつ対応版で更新反映が必要な場合だけ`拡張機能を再読み込み`を表示し、正式なreload経路を使います。音声runtimeの修復が必要な場合は小窓の`環境を修復`を使い、`LocalVoiceBridge.exe --setup`へコンソールなしで遷移します。通常利用者へ内部セットアップスクリプトを直接案内しません。

小窓は常に手前へ表示されます。×を押すと終了ではなく非表示になります。上部を左ドラッグすると移動でき、位置は次回起動時に復元されます。

## マイク会話モード

`マイク会話`は、Chrome版ChatGPTのモデル、Web検索、ログイン済み会話履歴をそのまま使いながら、入力だけをローカル音声認識へ置き換える任意モードです。既存の読み上げ専用利用ではオフのままにしてください。右Ctrl単独では録音せず、通常のCtrl操作へ干渉しません。

### 準備

1. `LocalVoiceBridge.exe --setup`を起動し、`読み上げ + マイク会話`プロファイルを実行して`faster-whisper`と`sounddevice`を導入します。
2. Windowsの設定でデスクトップアプリのマイクアクセスを許可し、既定の入力デバイスを選びます。
3. Chrome / Braveで拡張機能を正式なreload経路で更新し、ログイン済みのChatGPT会話画面を開きます。
4. Windows Local Voice小窓の`詳細設定`で文字起こしモデルと送信前猶予を設定します。その後、Windows Local Voice小窓で`マイク会話`をオンにします。選択したSTTモデルはこの時点で準備され、未取得なら`local-api/runtime/stt-models/`へダウンロードします。準備完了までは録音を開始しません。

初期STTモデルは`small`です。Windows Local Voice小窓の`詳細設定`から`medium`と`large-v3-turbo`へ変更できます。モデル変更時も先に準備状態へ入り、準備完了後に待機中へ戻ります。マイク会話の成功条件はCUDAの`float16`です。CUDA準備・推論・VRAMで失敗した場合はエラーとして停止し、CPUへ自動フォールバックしません。CPU実行は明示的な診断設定でだけ許可します。

### 操作

1. 入力先にしたいChatGPTタブの入力欄へフォーカスを入れます。
2. 右Ctrlを押したまま、右Shift左にある`＼ / _`キーを押すと、再生中のローカルTTSと未再生キューを破棄します。
3. 2キーを押している間だけ録音します。右Ctrl単独、左Ctrl、`＼ / _`キー単独、キーリピートでは録音を開始しません。
4. どちらか一方を離すと録音を終了し、日本語をローカルで文字起こしします。録音トリガーとして押した`＼ / _`は入力欄へ挿入しません。
5. 送信先は録音開始時に最後にフォーカスしていたChatGPT入力欄へ固定されます。文字起こし中に別タブへ移動しても変わりません。
6. 結果が空でなく、対象のChatGPT入力欄も空なら、今回の文字列をReact側へ反映される入力イベント付きで挿入します。
7. 初期値0.7秒の間にEscを押すと、今回挿入した文字列だけを削除して送信を中止します。猶予は小窓の`詳細設定`から0.0〜5.0秒へ変更でき、0秒では即送信します。
8. Escを押さなければ、有効になったChatGPTの送信ボタンを1回だけ押します。
9. 送信前に`submissionId`、タブ、ページ、会話、assistant基線をローカルAPIへ永続化し、ACKできた場合だけ送信ボタンを押します。返答候補が同じページ・会話内で1件だけに確定すると、そのassistant返答へbindします。
10. bind後は句読点で確定した文だけを最大2チャンク先読みし、Suguhaの`speed`プロファイルでローカル再生します。通常Autoの共通キューには入れないため、同じ返答を二重再生しません。読み上げ中の入力、Enter、送信ボタン、Regen、ページ遷移、同じ2キーで即座に失効・停止します。

対応版のYouTube Dictation Pause Controlが起動している場合、2キーが録音開始として確定した時点で`source=local-voice-bridge, active=true`を、どちらかを離した時点で`active=false`を`http://127.0.0.1:17654/state`へ送ります。通知はキーボードフックとは別スレッドで行い、通知先が停止中でも録音処理は中断しません。別ポートを使用する場合は`YOUTUBE_DICTATION_PAUSE_STATE_URL`を設定します。通知先は`http`のloopbackホストと`/state`に限定されます。

入力欄に既存文章がある場合、入力欄または送信ボタンを検出できない場合、ページ遷移が発生した場合は自動送信しません。既存文章を上書きまたは削除せず、小窓へ理由を表示します。

### 状態表示

小窓には`オフ`、`モデル準備中`、`待機中`、`録音中`、`文字起こし中`、`Escキャンセル待ち`、`送信関連付け中`、`ChatGPT応答待ち`、`逐次応答中`、`読み上げ中`、`エラー`を表示します。マイク権限、入力デバイス、STT依存関係、モデル、ChatGPT DOMの問題はエラー欄に具体的な確認先を表示します。

### ローカルデータと制約

録音はメモリ上だけで処理し、生の音声ファイルと文字起こし履歴は保存しません。ただし配送途中で消失しないよう、未ACKの文字起こしイベントは受け取り完了までローカルruntime状態へ一時保存します。またManifest V3 Service Workerや拡張機能の再接続後に読み上げ状態を復旧するため、直近assistant返答のチャンク、読み上げキュー、再生対象など必要最小限のブラウザruntime状態をローカルへ保存します。これらは会話履歴の収集用途ではなく復旧・再配信用です。structured runtime event logは本文・絶対パスを記録せず、2 MiBでローテーションして最大2世代のバックアップを保持します。Git管理外になるのはSTTモデル、録音・文字起こし用runtime領域、生成音声、参照音声、Chromeプロファイル、ログ、認証情報です。

TTSの生成音声は再生・Replay用に一時保存しますが、起動時と生成後に自動整理します。初期保持上限は最新1,000件、合計1GB、14日以内です。通知領域の`Clear generated audio...`は生成音声だけを削除し、参照音声、設定、STTモデルには触れません。

既知の制約は、Windowsの既定マイクだけを使用すること、ChatGPT入力欄・送信ボタン・assistant返答DOMの変更に影響されること、初回モデル取得にネットワークと空き容量が必要なことです。STTとIrodori v3のLive成功条件はNVIDIA GPU/CUDAです。CUDAが使えない場合は誤って遅い成功扱いにせず、原因を表示して停止します。

## 各ボタン

- `自動読み上げ`: オンにした後で、開いているすべてのChatGPTタブへ新しく表示されたassistant返答を監視します。同じ返答turnに最終操作のCopyボタンが現れ、生成停止と本文が1.2秒以上安定した時点を完了として扱います。オンにする前から表示されていた返答、生成中の途中断片、`思考中`・`考え中`・`Thinking`・`画像を分析しています`だけの途中状態は読みません。完了後に返答全文ではなく、冒頭プレビューだけを一度再生します。初期値は最大2行・80文字で、Windows詳細設定の`ブラウザの読み上げ範囲設定`から拡張Optionsへ移動して変更できます。
- `次へ`: 小窓に表示された手動操作対象の返答の次のチャンクへ進みます。
- `再生成`: 現在のチャンクを同じ設定で再生成します。
- `停止`: 現在の再生と未再生キューを停止・破棄します。
- `もう一度`: 再生成せず、直前に生成済みの音声をもう一度再生します。

Autoの読み上げ対象は最後に触った1タブだけではありません。開いている全ChatGPTタブです。各タブから届いた返答は1つの共通キューへ入り、順番に再生されます。手動操作対象と再生元は小窓のcontext行で確認できます。

完了検知は通常、各タブのDOMイベントで動きます。本文の安定待ちが必要なタブだけを短周期で再確認し、全ChatGPTタブの確認は取りこぼし復旧用として既定60秒間隔で行い、20秒未満にはしません。30タブ以上を開く通常運用で、全タブをサブ秒周期に巡回する設計は採用しません。

## 役割の分担

- `LocalVoiceBridge.exe`: Windows常駐アプリを起動し、`--setup`で正式セットアップ/修復導線を開く
- Windows Local Voice小窓: 日常の音声操作、状態表示、設定の入口、復旧操作
- Windows詳細設定: STTモデル、送信前猶予、Live TTSプロファイルをLocal APIの正本へ保存し、ブラウザ読み上げ範囲設定への明示的な入口を提供
- Local API: `referenceVoice`、音量、マイク会話、STTモデル、送信前猶予、Live TTSプロファイルの永続正本
- 通知領域: 小窓の表示、状態確認、再起動、フォルダ表示、自動起動、再セットアップ、終了
- Chrome / Brave拡張: 各ChatGPTタブの返答検出、共通キュー制御、Local API設定のbrowser mirror、音声再生状態通知
- Chrome / Brave拡張の設定画面: ブラウザ固有の読み上げ範囲`previewMaxLines` / `previewMaxChars`だけを編集
- デスクトップペット: 表示、左ドラッグ移動、左ダブルクリックによる小窓の開閉

ペットのシングルクリックと右クリックでは何も起きません。ドラッグ直後のダブルクリックは誤操作防止のため無効になります。

## GPU不要のデモ

```bat
npm ci
npx playwright install chromium
npm run demo
```

Node.jsとChromiumだけで安全なローカルフィクスチャを開きます。Python、CUDA、GPU、モデル、ChatGPTログインは不要です。実際の拡張機能コードと`scripts/mock-voice-api.js`を使用します。Chromiumを閉じるか`Ctrl+C`を押すと、mock APIと一時ブラウザプロファイルを片付けます。

デモではWindows小窓そのものではなく、同じloopback control APIを使って外部操作と拡張機能の境界を検証します。

## 自動テスト

```bat
npm run test:ci
```

`test:ci`は次を検証します。

- APIと音声URLが127.0.0.1のloopbackだけを使用すること
- Chrome内にLocal Voice操作パネルやペット本体を生成しないこと
- Windows小窓の設定・位置・表示状態が管理できること
- ペットの左ダブルクリックで小窓を開閉し、左ドラッグ後は誤開閉しないこと
- 外部小窓の`キャラクター`（保存キー`referenceVoice`）、`音量`、`自動読み上げ`、`マイク会話`が正しい設定ownerへ同期されること
- `キャラクター`がデスクトップペットAPIへ同期され、空または`none`は`placeholder`になること
- 自動読み上げをオンにする前から表示されていた返答へ`POST /v1/speak`を送らないこと
- Auto後の新しい返答だけを対象にし、生成中の長文や`思考中`などの途中状態を送信しないこと
- 20文字未満の短い返答も完了証拠が安定した後に読み上げること
- `次へ`、`再生成`、`もう一度`のコマンドを1回だけ実行すること
- 複数のChatGPTタブすべてが1つの共通Autoキューへ追加されること
- 外部小窓へ現在文章、キュー数、再生状態、登録タブ数、手動対象、再生元が同期されること

mockの成功は、実Irodoriの音質、GPU使用、将来の実ChatGPT DOMを保証しません。

### 実ChatGPTの完了ゲート

Autoの完了検知を変更した場合は、mock E2Eだけで完了扱いにせず、ログイン済みの実ChatGPTで次を確認します。音を鳴らさず検証する場合は先に`音量=0`へ設定します。

- 生成中の短い断片と長い本文のどちらもAutoキューへ入らないこと
- 同じ返答が成長または生成再開した場合、途中の完了候補が破棄されること
- Copy操作が現れて本文と完了証拠が安定した後だけ、同じ`messageKey`が一度Autoキューへ入ること
- 選択中ではないChatGPTタブでも同じ動作になり、全タブ共通キューを維持すること
- `/v1/control-panel`の対象`lastAssistantMessage`に`completionReason`と`completionObservedAt`が保存され、再接続後も消えないこと

確認後は変更前の音量へ戻します。上記の実サイト証跡がない場合は、実装済み・mock合格までとして扱い、実ChatGPT対応完了とは報告しません。

Live会話の17項目ゲートは次で実行します。

```bat
npm run test:live-e2e
```

ローカル実機のGPU/STT/Suguha測定証跡も必須にする場合は、`.ai-bridge`へ実測レポートを作成したうえで`node scripts/verify-live-e2e.js --require-hardware`を実行します。

## 実機Irodoriの確認

```bat
npm run test:e2e:real
```

先に`LocalVoiceBridge.exe --setup`を完了し、NVIDIA GPU、CUDA、モデルを用意してください。テストは専用loopbackポートと一時状態ファイルを使い、普段の8717番やペット設定へ干渉せずに次を確認します。

- 外部Autoによる実際の`/v1/speak`と生成音声取得
- 外部`次へ`による次チャンク再生
- 実Ref、Chrome保存値、デスクトップペット選択の一致
- 2つのChatGPTタブから同じ共通キューへ追加されること

ターミナルでサーバーログを直接確認する場合だけ`run-voice-stack.cmd`を使います。通常利用の起動入口ではありません。
