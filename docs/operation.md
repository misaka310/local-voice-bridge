# 操作と検証

## 通常の使い方

1. Windows検索または`LocalVoiceBridge.exe`からLocal Voice Bridgeを起動します。手動起動ではWindows Local Voice小窓を表示します。
2. 通知領域で`状態: Ready`または`状態: Ready (existing)`を確認します。
3. Chrome / BraveでLocal Voice Bridge拡張機能を読み込み、ChatGPTを開きます。
4. Windows小窓で必要に応じて`キャラクター`と`音量`を設定し、`自動読み上げ`をオンにします。
5. 開いている任意のChatGPTタブへ新しいメッセージを送り、返答完了後に冒頭プレビューが共通キューの順番で一度だけ再生されることを確認します。

Windowsログイン時の自動起動は`LocalVoiceBridge.exe --background`を使用し、小窓を勝手に前面へ出しません。すでに常駐中の状態で手動でもう一度EXEを開くと、新しい常駐プロセスを作らず既存小窓を表示します。通知領域アイコンのダブルクリックでも小窓を表示できます。デスクトップペットの左ダブルクリックは小窓の表示・非表示を切り替えます。

Chrome / Brave内にはLocal Voiceの日常操作パネルを表示しません。日常操作はWindows小窓の次のコントロールで行います。

- `キャラクター`
- `音量`
- `マイク会話`
- `自動読み上げ`
- `次へ`
- `再生成`
- `停止`
- `もう一度`
- `詳細設定`

`キャラクター`は内部の`referenceVoice`設定を使い、空IDは`標準`として表示します。同じIDのペット素材がある場合はデスクトップペットも連動します。

`自動読み上げ`と`マイク会話`は独立した利用者設定です。一方をオン・オフしても他方の永続設定を書き換えません。マイク会話中に通常Auto読み上げを一時抑制する場合はruntime phaseで扱います。

`詳細設定`ではSTTモデル、送信前猶予、Live TTSプロファイルを変更します。これらと`referenceVoice`、音量、マイク会話はLocal APIの永続設定が正本です。ブラウザ固有の読み上げ範囲だけは`ブラウザの読み上げ範囲設定`から拡張Optionsへ移動して変更します。

小窓には`Auto: 全3タブ · 操作対象: Tab B · 再生元: Tab A`のように、全タブAutoのscope、`次へ`/`再生成`の手動対象、現在または直前の再生元を表示します。

拡張機能の**切断**と**更新待ち**は別状態です。切断中は自己reloadの成功を示さず再接続を待ちます。接続済みかつ対応版で更新反映が必要な場合だけ`拡張機能を再読み込み`を表示します。音声runtimeの修復が必要な場合は小窓の`環境を修復`またはtrayの`終了して環境を修復`から`LocalVoiceBridge.exe --setup`へ進みます。

小窓は常に手前へ表示されます。×はアプリ終了ではなく非表示です。非表示中も同じcontrol-panel snapshot経路が低頻度で動き、マイク設定、再生状態、ペット状態を更新します。tray側に別の高頻度API polling系統は持ちません。

## 通知領域

通知領域メニューはWindows小窓と同じ日本語表示です。

- `状態: ...`
- `小窓を表示` / `小窓を隠す`
- `デスクトップペットを戻す`
- `Local Voice Bridge を再起動`
- `コントローラーログを開く`
- `生成音声フォルダーを開く`
- `生成音声を削除...`
- `参照音声フォルダーを開く`
- `Windows起動時に開始`
- `終了して環境を修復`
- `Local Voice Bridge をアンインストール...`
- `終了`

通知領域アイコンのダブルクリックは常に小窓を表示します。右クリックはメニューです。

## 初回オンボーディング

初回だけWindows小窓内で次を案内します。

1. Chrome / Braveへ`extension/`を読み込む
2. 拡張機能の接続を待つ
3. `テスト音声`で既存の`/v1/speak`経路を確認する
4. 成功したら完了状態を永続化する

オンボーディング完了後のWindows自動起動はbackground常駐に戻ります。手動起動は利用者の明示操作なので小窓を表示します。

## 各ボタン

- `自動読み上げ`: オンにした後、開いているすべてのChatGPTタブへ新しく表示されたassistant返答を監視します。生成中の途中断片、完了未確認、`思考中`・`考え中`・`Thinking`・`画像を分析しています`だけの途中状態は読みません。完了後、返答全文ではなく冒頭プレビューだけを一度再生します。
- `次へ`: 小窓に表示された手動操作対象の返答の次のチャンクへ進みます。
- `再生成`: 現在のチャンクを同じ設定で再生成します。
- `停止`: 現在の再生と未再生キューを停止・破棄します。
- `もう一度`: 再生成せず、直前に生成済みの音声を再生します。
- `詳細設定`: Windowsが所有するruntime設定を編集します。ブラウザ固有設定だけ拡張Optionsへ遷移します。

Auto対象は最後に触った1タブだけではありません。開いている全ChatGPTタブです。各タブの返答は1つの共通キューへ入り、順番に再生されます。完了検知は通常DOMイベントで動き、必要な返答だけ短周期で再確認します。全タブ確認は取りこぼし復旧用の低頻度処理であり、全タブをサブ秒周期に巡回しません。

## 拡張アイコン

拡張アイコンの左クリックはブラウザ固有のOptionsを開きます。日常操作をChrome側へ戻すものではありません。

Optionsが所有するのは`previewMaxLines` / `previewMaxChars`などブラウザ固有の読み上げ範囲です。STTモデル、送信前猶予、Live TTSプロファイルはWindows/Local API側が正本です。

## マイク会話モード

`マイク会話`は、Chrome版ChatGPTのモデル、Web検索、ログイン済み会話履歴をそのまま使いながら、入力だけをローカル音声認識へ置き換える任意モードです。読み上げ専用利用ではオフのままで構いません。

### 準備

1. `LocalVoiceBridge.exe --setup`を起動し、`読み上げ + マイク会話`を導入します。
2. Windowsでデスクトップアプリのマイクアクセスを許可し、既定入力デバイスを選びます。
3. Chrome / Braveで拡張機能を読み込み、ログイン済みのChatGPT会話画面を開きます。
4. Windows小窓の`詳細設定`でSTTモデルと送信前猶予を設定し、`マイク会話`をオンにします。

初期STTモデルは`small`です。`medium`と`large-v3-turbo`も選択できます。選択したモデルは有効化時または変更時に先に準備します。Live成功条件はCUDAの`float16`で、CUDA準備・推論・VRAMで失敗した場合はCPUへ暗黙フォールバックせずエラーとして停止します。

### 操作

1. 入力先にしたいChatGPTタブの入力欄へフォーカスします。
2. 右Ctrlを押したまま、右Shift左の`＼ / _`キーを押します。再生中のローカルTTSと未再生キューを先に停止します。
3. 2キーを押している間だけ録音します。右Ctrl単独、左Ctrl、`＼ / _`単独、キーリピートでは録音を開始しません。
4. どちらかを離すと録音を終了し、日本語をローカルで文字起こしします。
5. 送信先は録音開始時のChatGPT入力欄へ固定され、文字起こし中に別タブへ移動しても変わりません。
6. 結果が空でなく、対象入力欄も空なら文字列を入力します。既存文章は上書きしません。
7. 初期値0.7秒の送信前猶予中にEscを押すと、今回挿入した文字列だけを削除して中止します。0秒では即送信します。
8. Escを押さなければ、有効な送信ボタンを1回だけ押します。
9. 送信前に`submissionId`、タブ、ページ、会話、assistant基線をLocal APIへ記録し、ACK後だけ送信します。
10. assistant返答が一意にbindされた後は確定文だけを先読みしてローカル再生し、通常Autoの共通キューとは二重再生しません。

対応版のYouTube Dictation Pause Controlが起動している場合、録音中だけ`http://127.0.0.1:17654/state`へ`source=local-voice-bridge`のactive状態を通知します。通知先が停止中でも録音処理は中断しません。通知先はloopback `http`と`/state`に限定します。

### 状態表示

小窓には`オフ`、`モデル準備中`、`待機中`、`録音中`、`文字起こし中`、`Escキャンセル待ち`、`送信関連付け中`、`ChatGPT応答待ち`、`逐次応答中`、`読み上げ中`、`エラー`を表示します。

### ローカルデータ

録音はメモリ上で処理し、生の録音ファイルや文字起こし履歴として保存しません。未ACKの文字起こしイベント、Service Worker再起動に必要な直近runtime状態だけを復旧用に一時保存します。structured runtime event logは本文・絶対パスを記録しません。

TTS生成音声はReplay用に一時保存しますが、起動時と生成後に自動整理します。初期保持上限は最新1,000件、合計1GB、14日以内です。trayの`生成音声を削除...`は生成音声だけを削除し、参照音声、設定、STTモデルには触れません。

## 役割の分担

- `LocalVoiceBridge.exe`: Windowsアプリの起動、`--background`自動起動、`--setup`修復入口
- Windows Local Voice小窓: 日常操作、状態表示、設定入口、復旧操作
- Windows詳細設定: STTモデル、送信前猶予、Live TTSプロファイル
- Local API: `referenceVoice`、音量、マイク会話、runtime設定の永続正本
- Chrome / Brave拡張: ChatGPT DOM・タブ・browser設定とLocal Voice Bridgeの接続アダプター
- 拡張Options: ブラウザ固有の読み上げ範囲
- デスクトップペット: 表示、移動、小窓開閉の補助入口

## GPU不要のデモ

```bat
npm ci
npx playwright install chromium
npm run demo
```

Node.jsとChromiumだけでローカルフィクスチャを開きます。Python、CUDA、GPU、モデル、ChatGPTログインは不要です。

## 自動テスト

```bat
npm run test:ci
```

主な確認対象:

- Python設定・runtime・Qt小窓・tray契約
- first-run onboarding
- hidden時も同じsnapshot pipelineが継続すること
- Windows手動起動 / background自動起動 / 二重起動activation
- 日本語trayメニューと小窓表示導線
- Autoとマイク会話の独立
- 複数タブ共通キュー、手動対象、再生元
- 拡張toolbar→Options
- mock extension E2E

## 実ChatGPT / 実モデルの確認

Auto完了検知を変更した場合、mockだけで実ChatGPT DOMまで保証したとは扱いません。ログイン済み実ChatGPTで、生成途中を読まないこと、同じ返答を重複しないこと、完了後だけ読み上げることを確認します。

実Irodori確認:

```bat
npm run test:e2e:real
```

Live E2E:

```bat
npm run test:live-e2e
```

ハードウェア測定証跡を必須にする場合は`.ai-bridge`へ実測レポートを作成し、`node scripts/verify-live-e2e.js --require-hardware`を実行します。
